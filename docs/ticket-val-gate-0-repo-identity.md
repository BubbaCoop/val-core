# Ticket: `/val`'s Gate 0 does not check that it is running in the right repo with this library's agents

**Status:** open · **Raised:** 2026-09-17 · **Repo:** `@valiify/val-core` (this repo)
**Affected version:** 0.6.1 · **Order:** 2 — the second of the two Gate 0 guards
**Severity:** medium-high, rising · **Effort:** template text only

## What is missing

`templates/commands/design.template.md:61-73` runs two checks at Gate 0, "both cheap, both
fatal":

1. **The run directory must be inside the session's working directory.** `pwd` and compare.
   "Driving a run in repo A using agents generated for repo B produces output that looks right
   and was composed against the wrong library: the agents carry another library's class map,
   methodology path and package name."
2. **The generated agents must belong to THIS library.** Read the
   `GENERATED by @valiify/val-core@<v> from val/config.json (library: <name>)` header off
   `.claude/agents/design-concept-architect.md` and compare `<name>` against `library.name` in
   `val/config.json`. On a mismatch: STOP, tell the requester to run `npx val-init` here and
   start a new session.

Both values are recorded in the manifest's gate-0 note.

`templates/commands/val.template.md` Gate 0 step 4 checks only that the agents are *registered*:

> Confirm the val-* agents are registered in this session (they appear as subagent types).
> Generated agents register at session start; if they are missing, STOP […] — a prior run's
> Gates 1–3 silently fell back to general-purpose agents carrying the full tool set.

That catches *absent* agents. It does not catch *another library's* agents, which register just
as cleanly and carry the wrong everything.

## Why the risk is rising, not static

The generated header is written by `bin/val-init.mjs` into **every** template, `val-*` included
— the mechanism the check needs is already there and already correct. What has changed is the
consequence of getting it wrong:

- There are now **two** libraries with near-identical config shapes: same `paths` keys, same
  `runOutputDir` (`val/runs`), same `toolsDir` (`val/tools`), same registry path, same
  `tokenSource`. A wrong-repo run does not fail on a missing path.
- Their class vocabularies have **diverged**: `va-` / `va:` against `vd-` / `vd:`, both declared
  `strict`. A shortapp page built by dashboard's agents is not a page with a few wrong classes —
  it is a page whose every component class is namespaced to the wrong library.
- `paths.componentCss` points at `dist/index.css` in both, so the wrong library's stylesheet
  **resolves** rather than 404-ing. The page renders. It renders wrong.

The failure mode is specifically that it *looks right*. That is the sentence `/design`'s
template already uses, and it is more true of `/val`, because `/val`'s output is a rendered page
measured against a Figma frame — and the accuracy gate would report the mismatch as a large
number of genuine defects with no indication that the cause is the library rather than the build.

## Fix

Add both checks to `/val`'s Gate 0, mirroring `design.template.md:61-73`:

- `pwd`, compare the run directory against the session's working directory
- read the header of `.claude/agents/val-build.md` — the `/val` analogue of the design template's
  `design-concept-architect.md` — and compare `(library: <name>)` against `library.name` in
  `val/config.json`
- record both compared values in the manifest's gate-0 note, as `/design` does

Pick `val-build.md` deliberately: it is the agent that reads `{{COMPONENT_CSS}}`,
`{{TOKEN_SOURCE}}`, `{{REGISTRY_PATH}}` and `{{DESIGN_SYSTEM_SKILL_PATH}}`, so it is the one
whose substitutions do the most damage when they belong to another library.

Keep the existing registration check. These are different failures — absent agents versus wrong
agents — and both have happened in this codebase's history.

## Ordering with the plan-mode guard

Both are Gate 0 additions and should land together, but the plan-mode refusal goes **first** in
the gate: there is no point comparing a header if the run cannot write its own manifest. Final
Gate 0 order: plan-mode refusal → repo identity → create directories → manifest → agents
registered → registry freshness.

## Definition of done

`/val` invoked in a repo whose `.claude/agents/val-build.md` names a different library stops at
Gate 0, quotes both names, and tells the requester to run `npx val-init` and start a new session
— without creating a run directory.
