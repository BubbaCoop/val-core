feat: val-edit, a build contract, and instruments that say what they measured

From a Dashboard /val run of Business Account Review (two frames, eight build
passes, four reworks). Four defects passed every structural gate in that run,
two findings that drove work were themselves wrong, and a four-item edit cost
545k tokens. Each change below names the evidence that produced it.

Also cuts the CHANGELOG for 0.7.0, which was published on 2026-09-17 without
one — its content was already written and left sitting under [Unreleased], so
this dates the heading and moves it down. changelog.test.mjs is green and the
suite is 55/55.

--- new agent -----------------------------------------------------------

val-edit — stateless, scoped edits. Resuming val-build for a small change
carries the whole run forward: the build lane grew 352k -> 545k tokens while
the passes shrank to 5-7 tool calls, so ~99% of the spend was accumulated
context, not the edit. val-edit starts cold from three inputs (the page, the
fix list, 04-build/CONTRACT.md), budgets 10 tool uses, and cannot read the
extraction, requirements or methodology. val-build still owns initial builds
and structural rework, where the accumulated context is the point.

Its template opens with a warning aimed at whoever enables it: the agent is
only as safe as CONTRACT.md is accurate, and a thin contract does not degrade
gracefully — it yields an agent that confidently "corrects" a deliberate
inconsistency and reports success. The contract is the gate on adoption, not
the agent.

--- val-build -----------------------------------------------------------

Writes and maintains 04-build/CONTRACT.md: the invariants a later editor
cannot re-derive — values that look wrong and are correct, pinned geometry,
the rendering traps the library has already sprung, what the closed utility
set cannot express, and the verification required after any edit.

Diffs every extraction string against its own row, POSITIONALLY, before
declaring done. The run shipped fabricated verification statuses
("Middesk · Verified" where the design said "Middesk · DBA on file") past
twelve gates and a sign-off. Structural gates cannot see it: class audits
check classes, geometry checks boxes, and a tile diff reads swapped text of
similar length as a diffuse glyph-row residual indistinguishable from
antialiasing. A substring search does not catch it either — it passes when a
correct string sits on the wrong row. Unsourced strings are marked
data-val-awaiting-answer rather than filled plausibly.

--- val-qa --------------------------------------------------------------

Every probe prints the coordinate, value or resolved selector beside its
pass. Three instruments in one run returned "pass" while measuring something
true and irrelevant: an href that was correct while its symbol did not exist
in the sprite (eight glyphs rendered as nothing); a seam sampled at
section-bottom-minus-1, which for two of four sections was a real pixel 430px
from the seam under test; and an ink-mass comparison that flagged 66 of 70
rows both before AND after the fix that corrected them. Printing the
coordinate exposes all three immediately. Also states that an attribute
assertion is not a rendering assertion.

--- val-accuracy --------------------------------------------------------

Text findings inferred from geometry must be labelled span-evidence-only,
and the agent may not emit corrected text it has not read. It reported ~26
wrong rows across seven sections from ink-span alone; a glyph read of the
same rows found 49 of 54 correct, the spans having been attributed to
neighbouring rows. Dispatching it would have "corrected" 26 correct rows and
re-introduced the fabricated content the finding was meant to catch.

Adds region-scoped re-runs mirroring val-qa's tiers — one run re-scored 866
tiles to check four strings — and prefers ink span to ink mass, which is
unusable at 1x where the two rasterizers differ 10-30% on identical text.

--- orchestrator --------------------------------------------------------

Corroborate before dispatching: a geometry-inferred content finding needs a
second, different instrument before it drives a rework.

Run deterministic checks directly. A 72-test Playwright suite ran in ~3.5
minutes for zero model tokens after the QA agent stalled, against ~700k agent
tokens spent on earlier runs of the same file. An agent is needed to WRITE a
check and INTERPRET a failure, not to run one — and a gate run by the
orchestrator cannot be misreported to it.

Read CONTRACT.md before writing a fix list, and state remedies as
measurements rather than theories. One fix list measured a missing hairline
correctly and then said "copy the Registration rule to the owner sections" —
but that hairline belongs to a group row 31px inside the body, so following
it would have re-painted an existing seam and still missed the measured one.
The build agent caught it by measuring first.

Plus guidance on when to resume an agent and when to start cold.
